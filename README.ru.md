# Гаражный учет

[English version](README.md)

Небольшое self-hosted веб-приложение для учета домашних и гаражных расходников:
винтов, гаек, батареек, лент, клея, электрики и других вещей, которые обычно
исчезают ровно в тот момент, когда нужны.

## Возможности

- Вход по паролю, защищенная cookie-сессия и ограничение попыток входа.
- Рабочие разделы запасов, контейнеров, проектов, инвентаризации и покупок.
- Компактные карточный и списочный виды, нижняя навигация на телефоне.
- Добавление, редактирование, мягкое удаление и восстановление позиций.
- Поиск с опечатками и синонимами, фильтры по предметным сущностям.
- Быстрые операции из явно выбранного основного места хранения.
- Отмена операций без потери идентификатора и распределения остатков.
- Единый журнал пополнений, списаний, перемещений и инвентаризаций.
- Курсорная общая история и история конкретной позиции.
- Окно позиции с отдельными вкладками обзора, остатков, истории и описания.
- Фото и миниатюры в файловом хранилище, сжатые браузером перед загрузкой.
- Сканирование и генерация QR/штрихкодов через HTTPS.
- Распределение количества по местам и контейнерам с перемещением между ними.
- Нормализованные места, теги и проекты; позиция может входить в несколько проектов.
- Пошаговая инвентаризация по местам с прогрессом и применением при закрытии.
- Раздельные порог пополнения и желаемый запас.
- Печатный список покупок, рассчитанный до желаемого запаса.
- Светлая и темная темы.
- SQLite без отдельного сервера базы данных.

## Стек

- React
- TypeScript
- Vite
- Express
- встроенный в Node.js `node:sqlite`

Нужен Node.js 24 или новее, потому что backend использует `node:sqlite`.

## Архитектура

- `src/api` — типизированный клиент HTTP API.
- `src/components` — рабочие страницы, диалоги и предметные контролы.
- `src/domain` — типы и константы предметной области.
- `server/repositories` — пакетное чтение SQLite без N+1-запросов.
- `server/services` — транзакционная доменная логика.
- `server/routes` — изолированные HTTP-модули авторизации и файлов.
- `server/database.mjs` — последовательные миграции и резервные копии.

`stock_balances` является источником истины для количества и физических мест.
Общее количество в `items` поддерживается транзакционно как поисковый кэш.
Проекты и теги связаны с позициями отдельными many-to-many таблицами.

## Локальный запуск

Установите зависимости:

```bash
npm install
```

Создайте файл окружения:

```bash
cp .env.example .env
```

Отредактируйте `.env` и задайте реальный пароль:

```env
PORT=8782
HTTPS_PORT=8783
HTTPS_KEY=certs/garage.key
HTTPS_CERT=certs/garage.crt
GARAGE_PASSWORD=change-me
```

Соберите frontend:

```bash
npm run build
```

Запустите приложение:

```bash
npm start
```

Откройте:

```text
http://localhost:8782
```

## Разработка

Запустите backend и Vite dev server вместе:

```bash
npm run dev
```

Vite dev server проксирует запросы `/api` на backend на порту `8782`.

## Хранение данных

SQLite база создается автоматически:

```text
data/garage.sqlite
```

Папка `data/` намеренно исключена из git.

Перед миграциями при каждом запуске автоматически создается согласованная копия
базы в `data/backups/`. Дополнительно раз в сутки выполняется
`PRAGMA integrity_check` и создается очередная копия. По умолчанию сохраняются
14 последних копий. Ручной бэкап можно создать командой:

```bash
npm run backup
```

Для восстановления остановите приложение, замените `data/garage.sqlite`
выбранной копией и удалите оставшиеся файлы `garage.sqlite-wal` и
`garage.sqlite-shm`, если они существуют. После этого снова запустите процесс:

```bash
pm2 stop garage-inventory
cp data/backups/garage-YYYYMMDD-HHMMSS-mmm.sqlite data/garage.sqlite
rm -f data/garage.sqlite-wal data/garage.sqlite-shm
pm2 start garage-inventory
```

Фотографии и миниатюры находятся отдельно от SQLite:

```text
data/uploads/items/
```

Прежние изображения в base64 переносятся туда автоматически при первом запуске
новой версии.

## Деплой на домашний сервер

Простой вариант деплоя: держать приложение в пользовательской директории на
сервере:

```bash
cd ~/garage-inventory
npm ci
npm run build
npm start
```

Для постоянного фонового запуска можно использовать PM2:

```bash
pm2 start npm --name garage-inventory -- start
```

Приложение слушает порты из `.env`. Если настроен HTTPS, HTTP-порт отвечает
постоянным перенаправлением на HTTPS:

```text
http://192.168.1.82:8782
https://192.168.1.82:8783
```

## Обновление развернутой копии

В директории приложения на сервере:

```bash
git pull
npm ci
npm run build
pm2 restart garage-inventory
```

## Переменные окружения

| Имя | Обязательно | По умолчанию | Описание |
| --- | --- | --- | --- |
| `PORT` | Нет | `8782` | HTTP-порт; при настроенном HTTPS используется для перенаправления. |
| `HTTPS_PORT` | Нет | - | Дополнительный HTTPS-порт. Нужен для сканирования камерой с другого устройства. |
| `HTTPS_KEY` | Нет | - | Путь к приватному ключу HTTPS относительно корня проекта. |
| `HTTPS_CERT` | Нет | - | Путь к сертификату HTTPS относительно корня проекта. |
| `GARAGE_PASSWORD` | Да | - | Пароль для входа в приложение. |
| `GARAGE_SECURE_COOKIES` | Нет | Автоматически | Явное управление флагом `Secure` для тестов или доверенного TLS reverse proxy. |
| `BACKUP_ON_START` | Нет | `true` | Создавать согласованную копию SQLite перед миграциями при запуске. |
| `BACKUP_RETENTION` | Нет | `14` | Количество последних автоматических копий. |

## Заметки

Проект рассчитан на доверенную домашнюю сеть или VPN. HTTPS обязателен для
защищенной cookie-сессии и работы камеры с другого устройства.
